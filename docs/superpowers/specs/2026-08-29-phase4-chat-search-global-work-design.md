# Tashan OrgSpace Phase 4 聊天、搜索与全局工作设计

> 日期：2026-08-29
> 状态：用户已确认设计
> 前置依赖：文件、WorkItem、OKR、Partner、通知

## 1. 聊天

`Conversation` 类型为 direct/group，必须归属组织。direct 双方至少共同属于一个组织；group 只有群成员可读，管理员不自动加入。`Message` 使用 client_message_id 去重和 server_seq 排序；编辑、撤回和回应是追加事件。

HTTP 历史和持久游标是真源，WebSocket 只分发增量。断线按游标补齐。附件引用 FileEntry，不扩大权限。消息可转任务、会议、审批并建立双向 ResourceLink。

## 2. 合规读取

私聊正文默认仅双方。owner 合规读取必须提交理由、目标会话和时间范围，产生高风险审计并通知相关成员；禁止批量导出整个组织聊天。

## 3. 搜索

各领域提供授权过滤 provider。搜索聚合文件、工作项、OKR、Partner、成员和消息。结果与计数都执行授权；Membership 变化使缓存/索引授权失效。敏感 Partner 联系方式只做权限内精确匹配。

## 4. 我的工作与管理

我的工作跨组织聚合本人任务、审批、会议、提醒和 @消息，但只保存来源引用。打开时切换原组织。管理中心覆盖成员、角色、额度、通知制度、流程模板、Partner 待接管和审计，不自动读取个人空间、受限 Partner 或私聊正文。

## 5. 验收

覆盖消息去重/顺序/断线、无共同组织私聊、非群成员、撤回搜索、跨权限附件、消息转任务幂等、搜索推断、成员失效缓存、跨组织我的工作和合规读取。

## 6. 非目标

不实现音视频媒体服务器、跨组织私聊、公开群、端到端加密或 AI 自动回复。
