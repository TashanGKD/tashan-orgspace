# Tashan OrgSpace 完整前端蓝图

- 日期：2026-08-26
- 状态：待用户最终确认线稿
- 适用范围：完整 v1 Web 工作台，以及与 API、CLI、Skill 的统一交互契约
- 视觉基线：他山 T1 组织主题；标题 `Noto Serif SC`，正文 `Inter`，技术数据 `JetBrains Mono`

## 1. 核心判断

平台不是十几个相互独立的小应用，而是一个组织对象操作系统。所有模块使用同一种基本交互：

```text
空间 → 模块 → 对象列表 → 对象详情 → 对对象执行动作
```

模块之间变化的是对象 schema、列表列、详情分区、状态机和允许动作；空间、权限、关系、附件、评论、活动、通知、审计和确认机制保持统一。

“统一”只作用于控制面。文件 Blob、聊天消息流、计算调度、数据库卷和服务路由保留各自数据面，不能为了前端统一而塞进一张万能表。

## 2. 顶层信息架构

### 2.1 全局上下文

- `我的工作`：聚合本人在所有组织中的任务、审批、会议、@消息和提醒。
- `通知`：站内通知、短信状态、提醒历史。
- `全局搜索`：按当前可访问范围搜索人、任务、文件、流程、会话和服务。
- `账号与设备`：手机号、密码重置、设备 token、个人空间入口。

### 2.2 个人空间

- 概览
- 文件
- 计算与构建
- 服务、数据库与域名
- 用量与额度

个人空间只有本人可访问。组织管理员调整的是 entitlement，不因此获得个人空间读取权。

### 2.3 组织空间

- 概览
- 工作：任务、OKR、审批、会议
- 文件
- 计算与构建
- 服务、数据库与域名
- 对话
- 成员
- 制度与资源策略
- 审计

## 3. 通用页面语法

### 3.1 桌面结构

```text
┌ 顶栏：产品 / 空间切换 / 搜索命令 / 新建 / 通知 / 账户 ───────┐
├ 左侧模块导航 ┬ 中部对象列表 ┬ 右侧对象详情或完整详情页 ──────┤
│              │              │                                │
└──────────────┴──────────────┴────────────────────────────────┘
```

- 低复杂度对象使用右侧详情抽屉，保留列表上下文。
- 高复杂度对象使用可深链接的完整详情页。
- 移动端按“模块 → 列表 → 详情”逐层进入，不压缩成三栏。

### 3.2 通用列表页

列表页固定提供：

- 标题、说明、主新增动作。
- 状态统计与保存视图。
- 搜索、筛选、排序、分页或游标。
- 批量动作；只有服务端 capability 允许时才出现。
- 表格、紧凑列表、看板、日历等视图；同一查询结果不复制事实。
- 空、加载、部分失败、无权限和不可用状态。

### 3.3 通用详情页

详情由以下插槽组合：

- 标题、状态、所属空间、主要动作。
- 基础信息与负责人。
- 正文或配置。
- 关联对象。
- 文件与附件。
- 评论或会话。
- 当前流程、待办和允许动作。
- 活动时间线与审计摘要。

### 3.4 动作契约

每个动作绑定一个 capability，声明：权限、输入 schema、副作用、幂等性、确认级别、Web 表面、CLI 命令和审计动作。前端不自行判断最终授权，只用服务端结果决定成功、冲突、无权限或状态已变化。

## 5. 权限与状态呈现

- 不可见：服务端没有 read capability，导航和对象都不返回。
- 可见但不可操作：详情存在，动作按钮隐藏或禁用并说明所需角色。
- 状态冲突：服务器返回当前版本和允许动作，前端刷新详情，不静默覆盖。
- 组织全员可见任务/OKR按既定制度执行；受限流程、聊天和个人空间使用更严格规则。
- 管理员能够管理组织事实，但不因此读取个人空间或任意私聊正文。

## 6. 前后端解耦

Web 不直接访问文件系统、Docker、数据库或 SSH。页面只依赖版本化 API schema 与 SDK。后端业务层不返回前端组件结构；前端用模块定义、列表定义、详情分区和 capability 元数据组合 UI。

```text
服务端 capability registry
          ↓
Contracts / OpenAPI / SDK
  ┌───────┼──────────┐
 Web     CLI       Skill
```

每个正式用户功能必须同时具有：API capability、CLI 命令、Skill 安全说明、Web 列表/详情/动作表面或明确 deferred、权限测试、审计测试和 CI 覆盖门禁。

## 7. 通用前端组件

- `WorkspaceShell`：空间切换、导航、搜索、通知、账户。
- `ResourceListPage`：列表查询、筛选、排序、视图和批量动作。
- `ResourceDetailPage` / `ResourceDetailDrawer`：详情、关系、附件、活动。
- `ResourceActionBar`：基于 capability 和状态显示动作。
- `StatusBadge`、`ActorChip`、`DeadlineIndicator`、`QuotaMeter`。
- `RelationshipPanel`、`AttachmentPanel`、`ActivityTimeline`、`CommentThread`。
- `SchemaForm`：通用流程表单；领域扩展可以提供专用字段组件。
- `ConfirmationDialog`：普通确认、高风险确认、匿名公开确认。
- `PermissionBoundary`：仅用于前端呈现；最终授权仍由服务端执行。

## 8. 视觉和可访问性

- 默认采用 T1 青绿 `#4FA8AA`；暖橙 `#E8806A` 只用于提醒和关键风险。
- 页面以表格、紧凑列表和清晰详情分区为主，减少装饰性卡片。
- 状态不能只依赖颜色；同时使用文字、图标和形状。
- 键盘可完成空间切换、搜索、列表选择、详情动作和关闭抽屉。
- 所有危险动作明确对象、空间和不可逆后果。
- T1 Web 语义色、阴影、动效和无障碍 token 尚未成为正式品牌真源；开发时沿用当前产品可访问性基线，新增候选值必须单独确认。

## 9. 与未来 AI 员工的关系

AI 员工不是前端特例，而是 `Principal`/`Actor` 的一种。成员、负责人、审批人、消息发送者和审计 actor 的组件从第一版支持 actor 类型；v1 只显示 human/system，未来接入 `ai_employee` 时不改对象模型。

## 10. 验收标准

- 任一模块的第一管理页面都是列表或明确的摘要入口。
- 任一对象有可深链接详情和稳定对象 ID。
- 跨模块关联从详情页双向可追踪，但不扩大权限。
- Web、CLI、Skill 和 API capability 覆盖由 CI 检查。
- 个人/组织切换后，所有查询和动作都有服务端空间边界。
- 桌面三栏和移动逐层导航使用同一 URL 与数据模型。
- 所有页面包含加载、空、失败、无权限、只读和冲突状态。
