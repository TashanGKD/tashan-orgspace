## 通知旅程

通过真实 API、CLI、Worker 与 PostgreSQL 跑通：

- 审批请求与紧急任务立即生成站内通知和短信投递记录。
- 普通任务默认只生成站内通知；显式 `--send-sms` 才生成短信投递记录。
- DDL 和会议开始前一小时生成强制提醒。
- 合作方 `partner.created`、`partner.updated`、`partner.interaction_added` 等真实生产事件生成跟进提醒；改期会取消旧提醒，同一时间重复事件保持幂等。
- 每日汇总由 Worker 自动调度；成员关闭后，已创建但未发送的当日汇总立即取消；重新开启后可以恢复。
- 过期 Worker lease 被新 Worker 回收并完成提醒，证明重启恢复链路有效。
- 通知列表、详情、标为已读、每日汇总偏好、管理员时区版本均通过 CLI；相同幂等键只产生一条通知。

## 短信状态证据

短信状态严格区分平台意图、供应商受理和运营商送达：

- 模拟 E2E 中短信投递开关关闭，7 条记录保持 `pending`，没有外部网络请求。
- Provider fake 测试证明 `SendSms` 成功只写入 `accepted`，不会伪装为 `delivered`。
- BizId 查询测试证明只有查询到运营商最终状态后才写入 `delivered`；超时后先查询再决定是否重试。
- 日志和投递记录不保存手机号；手机号只在发送调用的内存边界内解析。
- 尚无真实阿里云网关受理或运营商送达证据。未获得用户明确批准前，不发送真实短信，也不把模拟结果写成真实送达。

## 本轮发现并修复的缺口

1. 每日汇总最初只有可调用方法，没有 Worker 自动入口；增加低频幂等扫描，并在组织 DomainEvent 到达时立即补排。
2. 合作方投影器最初监听测试专用事件名，生产服务不会产生；改为消费真实 Partner 事件，并补改期取消与去重。
3. 成员关闭每日汇总时，已排队的当天提醒原本不会取消；现在偏好更新和调度器共同处理取消与恢复。
4. 旧 API 集成测试硬编码 capability 数量；改为直接比较 capability 真源，避免下次扩展继续漂移。
